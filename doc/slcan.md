# slcan 仕様メモ

この文書は、slcan デバイス用 PC 側ビューワツールを実装するための仕様メモである。slcan は Serial Line CAN の略で、LAWICEL CAN232/CANUSB 由来の ASCII ベースのシリアルプロトコルを指す。USB 仮想 COM ポート、UART、RS-232 などを通して CAN フレームをテキスト行として送受信する。

## 参照元

- LAWICEL CAN232 Manual Version 3.0A, May 2012
  - https://www.manualslib.com/manual/2808618/Lawicel-Can232.html
- Linux kernel `slcan` ドライバ説明
  - https://cateee.net/lkddb/web-lkddb/CAN_SLCAN.html
- mac-can/SLCAN 実装の README
  - https://github.com/mac-can/SLCAN

## 基本フレーミング

- すべてのコマンドと受信フレームは ASCII テキストで表現され、行末は CR、つまり `\r` / ASCII 13。
- コマンドは大文字小文字を区別する。
- 正常応答は主に `\r`。エラー応答は BEL、つまり `\a` / ASCII 7。
- 数値は 16 進 ASCII で表現する。CAN ID、DLC、データバイト、タイムスタンプはいずれも固定桁の 16 進文字列として扱う。
- データフレームの DLC は Classical CAN の範囲で `0` から `8`。slcan の標準仕様は CAN FD を扱わない。

PC 側ビューワでは、シリアル入力を CR 区切りで行バッファリングし、先頭文字で行種別を判定する。BEL は CR 終端行ではなく単独エラーとして届く可能性があるため、受信処理では `0x07` を即時エラーイベントとして扱う。

## 接続と初期化

典型的な初期化手順は次の通り。

1. シリアルポートを開く。CAN232 の例では `57600bps, 8 data bits, no parity, 1 stop bit` が説明されているが、実機やファームウェアにより既定値は異なる。
2. CAN チャンネルが閉じている状態でビットレートを設定する。
3. 必要なら受信フィルタ、Auto Poll/Send、タイムスタンプを設定する。
4. `O\r` で通常モード、または `L\r` で listen-only モードを開く。
5. 受信行を継続的に読み、CAN フレーム行をパースして画面に反映する。
6. 終了時は `C\r` で CAN チャンネルを閉じる。

ビットレートやフィルタなどの設定系コマンドは、原則として CAN チャンネルを開く前に送る。送信系コマンドは通常モードで CAN チャンネルが開いている場合のみ有効で、listen-only モードでは送信できない。

## 標準ビットレート設定

`Sn\r` は定義済み CAN ビットレートを設定する。CAN チャンネルが閉じている時だけ有効。

| コマンド | ビットレート |
| --- | --- |
| `S0` | 10 kbit/s |
| `S1` | 20 kbit/s |
| `S2` | 50 kbit/s |
| `S3` | 100 kbit/s |
| `S4` | 125 kbit/s |
| `S5` | 250 kbit/s |
| `S6` | 500 kbit/s |
| `S7` | 800 kbit/s |
| `S8` | 1 Mbit/s |

一部実装では `S7` を 750 kbit/s として扱う例があるため、ツール側ではデバイス固有プロファイルで表記を調整できるようにする。LAWICEL CAN232 Manual Version 3.0A では `S7` は 800 kbit/s。

任意ビットタイミングは `sxxyy\r` で設定する。`xx` が BTR0、`yy` が BTR1 の 16 進値である。例: `s031C\r` は BTR0=`0x03`、BTR1=`0x1C`。

## チャンネル制御

| コマンド | 内容 | 条件 |
| --- | --- | --- |
| `O\r` | CAN チャンネルを通常モードで開く。送受信可能。 | ビットレート設定済み、チャンネル close 中 |
| `L\r` | CAN チャンネルを listen-only モードで開く。受信のみ。 | ビットレート設定済み、チャンネル close 中 |
| `C\r` | CAN チャンネルを閉じる。 | チャンネル open 中 |

PC 側ビューワは、監視専用なら `L` を優先できる。ただしデバイスやファームウェアにより `L` 非対応の場合があるため、設定 UI では通常モード `O` と listen-only `L` を選べるようにする。

## CAN フレーム表現

slcan の CAN フレーム行は、送信コマンドと受信通知で同じ形式を使う。

| 先頭文字 | 種別 | 形式 |
| --- | --- | --- |
| `t` | 標準 11bit データフレーム | `tiiildd...\r` |
| `T` | 拡張 29bit データフレーム | `Tiiiiiiiildd...\r` |
| `r` | 標準 11bit RTR フレーム | `riiil\r` |
| `R` | 拡張 29bit RTR フレーム | `Riiiiiiiil\r` |

フィールドの意味は次の通り。

- `iii`: 標準 ID。3 桁 16 進、範囲 `000` から `7FF`。
- `iiiiiiii`: 拡張 ID。8 桁 16 進、範囲 `00000000` から `1FFFFFFF`。
- `l`: DLC。1 桁、範囲 `0` から `8`。
- `dd`: データバイト。1 バイトを 2 桁 16 進で表す。データフレームでは DLC 個ぶん続く。

例:

```text
t10021133\r
```

標準 ID `0x100`、DLC `2`、データ `0x11 0x33` のデータフレーム。

```text
T0000010021133\r
```

拡張 ID `0x00000100`、DLC `2`、データ `0x11 0x33` のデータフレーム。

```text
r1002\r
```

標準 ID `0x100`、DLC `2` の RTR フレーム。

ビューワのパーサは、行長が DLC と一致するか必ず検証する。データフレームの場合、標準フレームは `1 + 3 + 1 + DLC*2` 文字、拡張フレームは `1 + 8 + 1 + DLC*2` 文字が基本長になる。RTR フレームにはデータバイトが付かない。

## タイムスタンプ

`Zn\r` は受信フレームへのタイムスタンプ付加を ON/OFF する。チャンネル close 中のみ有効で、設定は EEPROM に保存される実装がある。

| コマンド | 内容 |
| --- | --- |
| `Z0\r` | タイムスタンプ OFF |
| `Z1\r` | タイムスタンプ ON |

タイムスタンプ ON の場合、受信フレーム末尾の CR 直前に 4 桁 16 進のタイムスタンプが追加される。単位はミリ秒。例:

```text
t100211334D67\r
```

これは `t10021133\r` 相当の CAN フレームに、タイムスタンプ `0x4D67` が付いたものとして扱う。

パース時は、タイムスタンプ設定が ON の場合だけ末尾 4 桁を時刻として切り出す。ただし実機差や途中で設定が変わるケースに備え、行長から「タイムスタンプなし」と「タイムスタンプあり」の両方を判定できる実装が望ましい。

## 受信方式

受信方式は大きく 2 種類ある。

### Auto Poll/Send

`Xn\r` で Auto Poll/Send を ON/OFF する。チャンネル close 中のみ有効。ON にすると、受信 CAN フレームがシリアル側へ自動的に送られる。

| コマンド | 内容 |
| --- | --- |
| `X0\r` | Auto Poll/Send OFF |
| `X1\r` | Auto Poll/Send ON |

PC 側ビューワでは Auto Poll/Send ON を基本にする。これにより、PC 側はポーリングコマンドを送らずに受信行を読み続ければよい。

### 手動ポーリング

古い方式では `P\r` または `A\r` で FIFO を読み出す。

| コマンド | 内容 |
| --- | --- |
| `P\r` | 受信 FIFO から 1 フレーム取得 |
| `A\r` | 受信 FIFO から保留中の全フレーム取得 |

`P` はフレームがなければ CR のみを返す。`A` は最後に `A\r` を返す。新しい Auto Poll/Send 機能が有効な実装では、`P` と `A` が無効化され BEL を返す場合がある。

## 状態とエラー

`F\r` はステータスフラグを読む。応答は `Fxx\r`。`xx` は 8bit の 16 進値。チャンネル open 中のみ有効。

| bit | 意味 |
| --- | --- |
| 0 | CAN receive FIFO queue full |
| 1 | CAN transmit FIFO queue full |
| 2 | Error warning |
| 3 | Data overrun |
| 4 | 未使用 |
| 5 | Error passive |
| 6 | Arbitration lost |
| 7 | Bus error |

ビューワでは、BEL 応答、パース不能行、`F` のエラービットをイベントログに残す。`F` コマンドは赤色エラー LED のクリアを兼ねる実装があるため、定期ポーリングする場合は UI 上で副作用を明示する。

## フィルタ設定

`Mxxxxxxxx\r` は Acceptance Code Register、`mxxxxxxxx\r` は Acceptance Mask Register を設定する。値は 4 バイトぶんの 16 進で、LSB first として扱われる。CAN チャンネルが初期化済みで、まだ open していない時だけ有効。

この設定は SJA1000 の受信フィルタに依存するため、PC 側ビューワの初期実装では「全受信」を基本にし、フィルタ設定は高度な設定として切り出すのがよい。誤ったフィルタはフレームが見えない原因になる。

## デバイス情報

実装により、次の問い合わせコマンドが使える。

| コマンド | 応答例 | 内容 |
| --- | --- | --- |
| `V\r` | `Vhhss\r` | ハードウェア版 `hh`、ソフトウェア版 `ss` |
| `N\r` | `Naaaa\r` | シリアル番号 |

すべての slcan 互換デバイスが対応するとは限らない。非対応時は BEL または無応答になる可能性があるため、ビューワではタイムアウトを設ける。

## PC 側ビューワ実装上の注意

- シリアル受信はバイトストリームなので、CR まで蓄積してから 1 行として処理する。
- BEL はコマンド失敗として扱い、直前に送ったコマンドと関連付けて表示する。
- 受信行の先頭が `t/T/r/R` の場合は CAN フレームとして解釈する。`F/V/N/A/z/Z` などは制御応答として処理する。
- 送信コマンドと受信フレームが同じストリームに混在するため、コマンド応答待ちと非同期受信を分離する。
- Auto Poll/Send ON 時、送信成功応答が `z\r` または `Z\r` になる実装がある。単純に「CR だけが成功」と仮定しない。
- デバイスごとにサポートコマンドや既定シリアル速度が異なる。UI と設定ファイルにはデバイスプロファイルを持たせる。
- slcan は ASCII で扱いやすい一方、バイナリプロトコルより帯域効率は低い。高負荷 CAN バスの全フレーム監視では、シリアル速度と Auto Poll/Send、タイムスタンプ有無が取りこぼしに影響する。
- Classical CAN 前提のため、CAN FD フレーム、DLC 9 以上、BRS/ESI などは標準 slcan としては扱わない。

## 最小対応範囲

初期の PC 側ビューワでは、次を最小対応範囲にする。

- シリアルポート選択、ボーレート選択。
- `S0` から `S8` の CAN ビットレート選択。
- `O` / `L` / `C` によるチャンネル制御。
- Auto Poll/Send ON での非同期受信。
- `t/T/r/R` の受信パースと一覧表示。
- 任意で `Z0/Z1` によるタイムスタンプ表示。
- `F` によるエラー状態表示。

送信機能、フィルタ設定、BTR0/BTR1 直接指定、デバイス情報取得は、基本ビューワが安定してから追加する。
